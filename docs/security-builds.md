# 안전한 빌드와 검증 산출물

`npm run build`와 데스크톱 패키징은 같은 웹 빌드를 사용합니다. 필요한 입력을 검사한 뒤 임시 작업 폴더에 복사하고, Vite가 새 폴더에 만든 번들을 완성된 디렉터리 단위로 게시합니다. 입력과 산출물에 연결 파일·정션·특수 파일이 있으면 빌드를 중단합니다. 브라우저·데스크톱 테스트도 임시 폴더에 기록한 뒤 결과를 게시합니다. Vite 개발 서버는 루프백에만 바인딩하며 빌드·릴리스·진단·스테이징 폴더를 제공하지 않습니다.

빌드와 프로젝트 저장은 권한이 제한된 작업 폴더에서 실행합니다. POSIX의 빌드 경로 검사는 다른 사용자가 쓸 수 있는 산출물 부모도 거부합니다. Windows에서는 폴더의 NTFS 권한을 관리자가 설정해야 합니다. 공유 폴더에서 프로젝트를 교체할 때 대상 파일에 별도로 지정한 ACL의 보존은 보장하지 않습니다.

## 정식 Windows 배포

1. 신뢰할 수 있는 Windows 릴리스 환경에 유효한 Authenticode 코드 서명 자격 증명을 준비합니다. electron-builder가 지원하는 서명 환경을 구성하고, 게시자 인증서의 지문을 `MOTOR_SIGNER_THUMBPRINT`에 지정합니다.
2. `npm run package:desktop:signed`를 실행합니다. 이 명령은 패키징에 코드 서명을 요구하고, 설치 EXE와 내부 Motor Lab EXE 모두의 포함 서명, 게시자 지문, 타임스탬프를 검사한 뒤 체크섬과 함께 게시 폴더로 옮깁니다.
3. 배포본을 별도로 검사하려면 신뢰할 수 있는 경로에서 제공된 게시자 지문으로 Windows PowerShell에서 `scripts/verify-signature.ps1 -Path <설치 EXE> -ExpectedThumbprint <지문>`을 실행합니다. SHA-256은 내려받은 파일의 바이트 일치 여부를 확인하는 데 사용합니다.

일반 `npm run package:desktop`과 GitHub Actions 검증 작업은 서명 자격 증명 없이 실행할 수 있습니다. 기존 unsigned 배포본에도 Windows 게시자 경고가 표시될 수 있습니다. 검증 작업은 실제 패키지의 Electron Fuses와 시작을 확인합니다. Playwright의 네이티브 대화상자 테스트는 별도로 복사한 테스트 EXE에 Node 검사 기능만 활성화합니다.

이 절차는 파일 경로와 배포 산출물의 경계를 보호합니다. 빌드 계정으로 실행하는 소스 코드나 npm 실행 스크립트는 별도 검토가 필요합니다.
